# btp-deploy-doctor

CLI and library that check SAP CAP / MTA projects for deployment mistakes and explain Cloud Foundry deploy logs.

```sh
btp-doctor check [dir]                 # static checks on mta.yaml, package.json, .cdsrc.json
btp-doctor fix [dir] --dry-run         # preview automatic fixes
btp-doctor fix [dir]                   # apply them
btp-doctor diagnose deploy.log         # explain a saved log
cf deploy mta_archives/x.mtar 2>&1 | btp-doctor diagnose
btp-doctor diagnose --app my-srv       # runs cf logs my-srv --recent
btp-doctor diagnose --mta-op <id>      # runs cf dmol -i <id>
```

Add `--json` for machine-readable output. `check` exits 1 when it finds errors, so it can gate CI.

## Automatic fixes

`fix` applies every fix that needs no decision, one at a time, re-checking the project after each. Edits are minimal: comments, key order and formatting elsewhere in mta.yaml and package.json are kept. A fix is refused if the file changed since it was computed. Findings with several possible fixes (for example two similar dependency names) are left for you to choose in the editor.

After fixes that change package.json, run `npm install` so package-lock.json matches.

## Rules

Rules marked ✔ have an automatic fix (sometimes only when the right value is unambiguous).

| ID | Severity | Checks | Fix |
|---|---|---|---|
| MTA001 | error | mta.yaml is valid YAML |  |
| MTA002 | error/warning | ID and _schema-version present | ✔ |
| MTA003 | error | Names unique across modules, resources, provides |  |
| MTA004 | error | Every `requires` entry resolves | ✔ |
| MTA005 | error | Module paths exist, or are generated by a `cds build` before-all step | ✔ |
| MTA006 | error | HDI deployer has exactly one target container | ✔ |
| MTA007 | error | Managed services have service and plan | ✔ |
| MTA008 | error | XSUAA security descriptor file exists | ✔ |
| MTA009 | warning | Approuter has xs-app.json |  |
| MTA010 | warning | CAP service memory at least 256M | ✔ |
| MTA011 | warning | `cds build` is run with npx and a pinned @sap/cds-dk | ✔ |
| CDS000 | error | package.json / .cdsrc.json are valid JSON |  |
| CDS001 | error | HANA in production has a runtime driver | ✔ |
| CDS002 | error | Real auth has @sap/xssec | ✔ |
| CDS003 | warning | HDI deployer in mta.yaml matches CAP production db |  |
| CDS004 | warning | No real auth in the development profile | ✔ |
| CDS005 | error | @sap/cds is a runtime dependency | ✔ |
| CDS006 | warning | No mock auth in production |  |
| CDS007 | warning | No SQLite in production |  |
| CDS008 | info | Node version pinned |  |
| X001 | error | CAP service module is bound to the auth service it is configured for | ✔ |
| X002 | error | Destinations used by CAP have the destination service bound | ✔ |
| REPO001 | warning | Credential files are git-ignored | ✔ |

The log analyzer knows the failure signatures in `src/logs/patterns.ts`.
